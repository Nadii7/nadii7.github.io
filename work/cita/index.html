The challenge

One appointment combines services, time, family and insurance.

Give booking a clear state model and a named feature action.

The booking controller delegates to a use-case provider and repository. Freezed state keeps the selected date, time, service, family member and insurance together, so the view can reflect one explicit booking state.

The trade-off

These boundaries add types, providers and generated code. They also make the feature’s state and data dependencies easier to locate as the booking flow grows.

Evidence in the implementation

Recent authored work also includes guest access, map actions and UI updates. The source separates booking actions, repository contracts and remote requests.
